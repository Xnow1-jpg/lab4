# Отчёт по лабораторной работе №4: «Написание Unit-тестов»

---

## 1. Цели и задачи тестирования

* **Цель**: автоматизированная проверка корректности вычисления геометрических характеристик (площади и периметра) для набора геометрических фигур при помощи модульного тестирования.


* **Задачи**:


* Разработать тестовые сценарии с использованием фреймворка `unittest` для модулей `circle.py`, `rectangle.py`, `square.py` и `triangle.py`.


* Проверить функции на стандартных целочисленных значениях, единичных отрезках и граничных случаях (нулевые параметры).
* Выявить возможные логические дефекты и несоответствия формул в существующих реализациях функций без изменения исходного кода самих библиотек.


* Зафиксировать результаты выполнения тестов и оформить выводы по качеству продукта.





---

## 2. Описание тестируемого продукта

Тестируемый продукт представляет собой библиотеку математических модулей на языке Python для расчёта геометрических параметров базовых двумерных фигур:

* **Круг (`circle.py`)**: функции `area(r)` (вычисление площади через радиус) и `perimeter(r)` (длина окружности).
* **Прямоугольник (`rectangle.py`)**: функции `area(a, b)` (площадь по двум сторонам) и `perimeter(a, b)` (периметр).
* **Квадрат (`square.py`)**: функции `area(a)` (площадь по стороне) и `perimeter(a)` (периметр).
* **Треугольник (`triangle.py`)**: функции `area(a, h)` (площадь по основанию и высоте) и `perimeter(a, b, c)` (периметр по трём сторонам).

---

## 3. Область тестирования

Тестированию подлежат исключительно публичные интерфейсные функции модулей:

* `circle.py`: `area(r)`, `perimeter(r)`.
* `rectangle.py`: `area(a, b)`, `perimeter(a, b)`.
* `square.py`: `area(a)`, `perimeter(a)`.
* `triangle.py`: `area(a, h)`, `perimeter(a, b, c)`.

Вне области тестирования: производительность выполнения на больших массивах данных, стресс-тестирование, графический интерфейс (отсутствует).

---

## 4. Стратегия тестирования

* **Уровень тестирования**: модульное (unit-тестирование).


* **Подход**: метод «чёрного ящика» (Black Box Testing) — тестовые случаи формируются строго на основе математических спецификаций и формул геометрии, без опоры на внутреннюю структуру кода.


* **Применяемые техники тест-дизайна**:
* Классы эквивалентности (положительные натуральные числа, вещественные числа).
* Анализ граничных значений (нулевые длины сторон и радиусы).


* **Инструментарий**: встроенная библиотека Python `unittest`. Запуск наборов тестов осуществляется через механизм автообнаружения: `python -m unittest discover -s tests`.



---

## 5. Критерии приёмки

1. Для всех 4 модулей написаны автономные тестовые классы, унаследованные от `unittest.TestCase`.


2. Код тестов размещён в отдельной директории `tests/` репозитория и зафиксирован коммитом в системе контроля версий Git.


3. Исходный код геометрических фигур остался неизменным (`git status` фиксирует изменения только в тестах и отчёте).


4. Все тесты запускаются и завершаются штатным формированием отчёта раннера `unittest`.


5. Для каждого упавшего теста локализована причина и зафиксирован дефект в коде фигуры.



---

## 6. Ожидаемые результаты

* Успешное прохождение тестов для корректно реализованных геометрических формул (вывод `OK` в консоли).


* Корректная фиксация ошибок (статус `FAILED`) для функций, в которых допущены математические или алгоритмические ошибки (пропуск коэффициентов, неверные операции).


* Сформированный протокол прогона тестов с указанием количества выполненных тестов и трейсбеками падений.

## 8. Выводы из результатов тестирования

* Разработанный комплект unit-тестов полностью покрыл заявленную функциональность модулей геометрической библиотеки.


* Принцип тестирования «чёрного ящика» позволил независимо выявить 2 критических бага в исходных файлах без предварительного анализа их исходного кода:


1. В `rectangle.py` функция `perimeter(a, b)` не учитывает умножение полупериметра на 2 (формула реализована как `a + b`).
2. В `triangle.py` функция `area(a, h)` не выполняет деление произведения основания на высоту на 2 (формула реализована как `a * h`).


* Падение тестов в рамках данной лабораторной работы подтвердило эффективность тестового покрытия: дефекты алгоритмов были своевременно обнаружены до интеграции модулей в конечное ПО. Исходный код библиотек оставлен в исходном виде согласно регламенту задания.
